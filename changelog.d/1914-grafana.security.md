Grafana no longer starts with its built-in `admin` / `admin` login (part of #1914; the loopback port bindings were done in #1955). The compose file now reads the admin password from `secrets/grafana_admin_password.txt`, which all three secrets generators (Linux, macOS, Windows) create with a random value, and the container refuses to start when that file is missing or empty (it would otherwise fall back to `admin`; Docker also creates a directory for a missing bind source, which the check rejects). Checked against the pinned Grafana image: a missing or empty file exits 1 with a message, and with a generated password `admin`/`admin` and a wrong password both get 401 while the generated one gets 200. **Action for existing installs:** run the secrets generator, then reset the password in the existing Grafana volume (Grafana applies the environment password only when it first creates its database): `docker compose exec grafana grafana cli admin reset-admin-password "$(cat secrets/grafana_admin_password.txt)"`. The password file is mode 644 on Linux like the other compose-mounted secrets (a container user must read it; see the open question in #1912). README and `docs/monitoring_stack.md` no longer advertise `admin` / `admin`.
