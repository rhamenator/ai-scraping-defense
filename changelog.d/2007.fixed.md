The Admin UI rate limit now counts failed sign-ins only (#2007). It used to count every authenticated request, and one dashboard page load makes several, so opening a second page within a minute answered `429` and the dashboard showed `Blocklist unavailable: [object Object]`. A correct password is no longer rate limited; `ADMIN_UI_RATE_LIMIT` (default 5) wrong attempts per `ADMIN_UI_RATE_LIMIT_WINDOW` (default 60 s) per address still stops password guessing, and the `429` now carries `Retry-After` and a readable message. The console's scripts show the server's error text instead of `[object Object]`. Both settings are now documented in `docs/configuration.md`.
